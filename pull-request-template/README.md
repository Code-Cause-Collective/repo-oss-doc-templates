# Pull Request Templates

A Pull Request (PR) template helps contributors submit consistent and complete pull requests. It ensures maintainers have all the information needed to review changes efficiently and reduces back-and-forth questions.

## Examples

> [!NOTE]
> The examples *we* provided are opinionated and intended as guidance. We encourage you to explore other approaches, adapt them to your workflow, and expand upon them to fit the specific needs of your project.

- [pull_request_template.md](/pull-request-template/pull_request_template.md)

Common key elements to include in a PR template:

1. **Title**
   - A concise description of the change.
   - Follow any branch or commit naming conventions.

2. **Description / Summary**
   - What does this PR do?
   - Why is the change needed?
   - Link to related issues or tasks.

3. **Type of Change**
   - Bug fix, feature, documentation update, refactoring, etc.
   - Helps maintainers prioritize reviews.

4. **Additional Notes**
   - Any additional context, warnings, or considerations.
   - Related PRs or dependencies.

> [!NOTE]
> The structure of a pull request template is often opinionated, with different teams emphasizing different details. We encourage you to explore various formats and adapt a style that works best for your project as you refine your release and contribution process.
