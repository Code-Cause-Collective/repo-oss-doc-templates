# Contributing

A `CONTRIBUTING.md` file is used to guide new contributors on how to get involved in your project. Including a clear contributing guide helps maintainers manage contributions smoothly and encourages a healthy community.

## Examples

> [!NOTE]
> The examples *we* provided are opinionated and intended as guidance. We encourage you to explore other approaches, adapt them to your workflow, and expand upon them to fit the specific needs of your project.

- [CONTRIBUTING.md](/contributing/CONTRIBUTING.md)

Common key elements yo include in a contributing document:

1. **Introduction**
   - Explain the purpose of the project and why contributions are welcome.
   - Set a positive, encouraging tone for new contributors.
2. **How to Contribute**
   - Step-by-step instructions for submitting issues, pull requests, or feature requests.
   - Include branch naming conventions, commit message style, and workflow details.
3. **Code of Conduct**
   - Reference your `CODE_OF_CONDUCT.md` to promote respectful and inclusive collaboration.
4. **Development Setup**
   - Provide instructions to set up the development environment locally.
   - Mention required tools, dependencies, and commands to run tests.
5. **Style Guides**
   - Include coding standards, formatting rules, or linting requirements.
   - Ensure consistency across contributions.
6. **Testing**
   - Explain how to run existing tests and write new ones.
   - Encourage contributors to test changes before submitting.
